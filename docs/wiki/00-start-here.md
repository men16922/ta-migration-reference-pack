# 00. 시작 — 포팅 에이전트 운영 지침

> **요약**: 이 저장소의 기능을 회사 프로젝트의 메뉴 하나(예: `온프렘 IDC`)로 재구현한다. 코드를 복사하지 말고, 회사 저장소의 스택·규칙에 맞게 **동작을 이식**한다.
> **근거 소스**: 이 위키 전체, `kit/src/onprem_atlas/`, `src/console/`
> **관련 페이지**: [01](01-product-scope.md), [40](40-porting-playbook.md), [42](42-acceptance-tests.md)

## 1. 임무

회사 저장소(이하 **호스트**)에 다음을 제공하는 메뉴를 추가한다.

1. **Excel 업로드 → 자동 증분 동기화**: ESM에서 내려받은 `.xlsx` 여러 개를 올리면 시트 종류를 자동 판별하고, 같은 자산(식별 키 동일)은 **최신 값으로 덮어쓰고(overwrite)**, 파일에 없는 기존 자산은 유지한다. → [12](12-auto-incremental-sync.md)
2. **온프렘 IDC 대시보드**: 자산·업무 시스템·WEB/WAS/DB 인스턴스·최근 변경 KPI, 업무별 자산, 센터별 분포. → [30](30-dashboard.md)
3. **아키텍처 구성도**: IDC 전체(센터별 집계)와 업무 시스템별 배치도, draw.io 내려받기. → [31](31-diagram-engine.md)
4. **업무 시스템·자산·인스턴스 조회와 변경 이력**. → [33](33-ui-pages-and-menu.md)
5. (선택) draw.io 수동 편집과 편집본 이력. → [32](32-diagram-editor-drawio.md)

## 2. 절대 규칙

- **호스트 규칙이 우선한다.** 언어, 프레임워크, 폴더 구조, 린트, 테스트, 디자인 시스템, 인증, DB 마이그레이션 방식은 호스트를 따른다. 이 저장소의 Carbon·SQLite·FastAPI는 참고 구현일 뿐이다.
- **동작 불변식은 지킨다.** 식별 키, 헤더 매핑, 값 정규화, 원천(source) 분리, 업무 분류 우선순위, 추정 금지 원칙(IP로 서브넷·통신선을 만들지 않음)은 [10](10-data-model.md)·[11](11-excel-ingest.md)·[14](14-business-classification.md)·[31](31-diagram-engine.md)의 "불변식" 절 그대로 옮긴다.
- **실데이터 금지.** 테스트·fixture·문서에는 합성 데이터만 쓴다. IP는 `192.0.2.0/24`, `198.51.100.0/24`, `203.0.113.0/24`(문서용 대역)만 쓴다.
- **결정 필요 항목(D-번호)은 기본값으로 구현하고 기록한다.** 기본값을 바꾸려면 사람에게 확인한다. → [결정 목록](40-porting-playbook.md#결정-필요-항목)
- **제외 범위를 다시 만들지 않는다.** 이관 준비도 점수, FPMS/네트워크 실험실, 방화벽 자동 허용, IP 기반 서브넷 추정은 포팅하지 않는다. → [01](01-product-scope.md)
- **보안 경계를 낮추지 않는다.** 현재 코드의 loopback 전용 쓰기 검사는 호스트 인증·권한으로 **대체**한다. 단순 제거 금지. → [41](41-host-integration.md)

## 3. 작업 루프 (단계마다 반복)

1. **읽기**: 해당 단계의 위키 페이지와 근거 소스 파일만 읽는다.
2. **조사**: 호스트에서 같은 종류의 기존 코드(메뉴, API, 테이블, 업로드, 차트)를 찾아 패턴을 따른다.
3. **계획**: 바꿀 파일과 테스트를 `templates/porting-log.md` 양식으로 적는다.
4. **구현**: 작은 단위로 구현한다. 공용 코드 변경은 최소화한다.
5. **검증**: 호스트의 린트·타입체크·테스트를 실행하고, [42](42-acceptance-tests.md)의 해당 단계 테스트를 통과시킨다.
6. **기록**: 결과, 결정(D-번호), 남은 문제를 작업 기록에 남긴다.

단계 순서와 종료 조건은 [40-porting-playbook](40-porting-playbook.md)에 있다. **P0(호스트 조사)을 건너뛰지 않는다.**

## 4. 완료 기준 (Definition of Done)

- [ ] 호스트 메뉴에 `온프렘 IDC`(이름은 D-11) 항목과 하위 화면이 보이고, 권한 없는 사용자는 접근할 수 없다.
- [ ] 여러 `.xlsx`를 한 번에 올리면 시트별 종류가 자동 판별되고, [fixtures/sync-scenarios.json](fixtures/sync-scenarios.json)의 시나리오가 모두 통과한다.
- [ ] 같은 파일 재업로드는 변경 0건으로 끝나며 데이터 버전이 증가하지 않는다.
- [ ] 대시보드 KPI·업무별 자산·센터별 분포가 [fixtures/api/summary.json](fixtures/api/summary.json)과 같은 의미의 값을 보여준다.
- [ ] IDC/업무 구성도가 결정적(같은 입력 → 같은 좌표·XML)이고, 겹침·부모 이탈이 없으며, `.drawio`로 내려받아 draw.io에서 열린다.
- [ ] 자산 상세에서 원본 파일·시트·행·원문 값을 확인할 수 있다.
- [ ] 5,000행 업로드가 호스트 환경에서 합리적 시간(기준: 처리 5초 이내, D-12) 안에 끝난다.
- [ ] 호스트 CI 전체가 통과한다.
