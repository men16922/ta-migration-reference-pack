# ESM 기반 사내 IDC 구성도 도구

2026-10-21 사용자 요청 기준. 기존 P8 우선순위보다 이 계획을 우선한다.
목표는 실제 ESM Excel을 등록해 자산과 구성도를 관리하고, 별도 지식을 AI Agent가 근거와 함께 검색하는 업무 도구다.

## 확인한 입력과 판단

- `sample/sample1.png`, `sample2.png`: 서버 Excel의 좌우 영역. 그룹사(BOX/OS), 설치지역, 호스트명, 대표/관리 IP, 용도, BOX 제조사/모델/시리얼, OS 범주/종류/버전, ITSM 업무 계층, CPU Core(ea), Memory(GB), EOS, 설명, 이중화서버 등이 보인다.
- `sample/sample3.png`: 장비 Excel. 그룹사명, 설치지역, 장비명, 상면번호, 장비범주/세부분류, 제조사/모델/S/N, 랙시작위치, 사용, 관리/서비스 IP, 설명 등이 보인다. SAN SWITCH, NAS, SAN, 백업장비를 서버/L3로 오분류하면 안 된다.
- `sample/sample4.png`: ESM DISK 성능 조회. 날짜/호스트/디스크별 평균 사용률과 용량을 보여준다. CPU/메모리 조회·파일 내보내기는 미확인이다.
- `sample/sample5.png`~`sample11.png`: WEB/WAS/DB 인스턴스 목록. 제품·버전·포트, WEB URL, DB SID/이중화 방식, 호스트·그룹사·설치지역·업무 계층을 확인했다. 동일 호스트의 여러 행은 별도 서버가 아니다.
- `sample/sample12.png`: 보안장비 목록. 솔루션 유형/관리IP/OS버전/제조사/모델/S/N/동작방식/정·부 담당자/모니터링 여부 등. 별도 보안 원천과 유형별 표기를 사용하고 Active/Standby만으로 HA 관계를 만들지 않는다.
- 이미지는 헤더 구조를 판단하는 근거다. 잘린 헤더·셀 값·실제 파일 형식은 확정하지 않으며 실제 자산 행을 OCR로 복원해 운영 DB에 넣지 않는다.
- ESM은 사용자 SSO 로그인 후 Excel 다운로드가 현재 수집 경로다. 다운로드 이후 등록·검증·저장·구성도 생성은 자동화할 수 있다.
- SQLite는 저장소다. Zabbix/ESM에서 수집한 사용률도 저장 가능하지만 DB 자체가 원격 사용률을 수집하지는 않는다.

## 제품 범위

| 유지/구현 | 제외 |
|---|---|
| Excel 등록·검증, 자산 검색·상세, 업무 분류, IDC/업무 구성도, draw.io 내보내기, 등록·변경 이력 | FPMS 실험실, 방화벽 자동 허용, 벤더 CLI 생성, 정책 감사, Batfish/Containerlab, AWS 비교·배포, 임의의 이관 준비도 점수 |
| 별도 지식 저장소와 회사 AI Agent용 검색 도구 | 중복 정책 챗봇, 중복 용량산정 엔진, 임의의 실데이터·관계 생성 |

## 구현 순서와 완료 기준

1. **E0 화면 정리 및 운영/검증 데이터 분리**: 필요한 메뉴만 남기고 기존 운영 DB를 보존하여 기동한다. 신규 DB는 빈 상태로 시작한다. 테스트 데이터는 별도 DB에서만 검증한다.
2. **E1 실제 Excel 등록**: 업로드 → 시트·헤더/필드 매핑 확인 → 오류/변경 미리보기 → 확정. 서버/장비 등 원천별 최신본을 합쳐 현재 자산을 만든다. 다른 원천 삭제 방지, 파일 해시·행·실행 출처, 중복/충돌/동시 등록 검증. 부분 조회 Excel은 전체 원천을 대체하지 않도록 명시적 등록 모드가 필요하다.
3. **E2 자산 모델과 구성도**: 대표/관리/서비스 IP, 그룹사, 설치지역, 상면·랙 시작 U, 물리 장비/OS 구분, ITSM 업무 계층, 설명, 이중화 대상 보존. 업무는 명시적 ESM 계층을 우선하며 이름 규칙은 확인된 프로파일에만 사용한다.
4. **E3 지식과 Agent 검색**: 운영 DB와 별개 지식 저장소에 업무 설명·운영 절차·표준·확인된 관계 문서를 버전/출처/권한과 함께 저장. 자산 검색·상세·구성도 열기와 지식 검색을 별도 읽기 도구로 회사 Agent에 연결. 답변은 자산 실행/행 또는 문서/버전을 인용하고 불명확하면 미확인으로 남긴다. MCP 없이 Python 도구/HTTP 계약을 제공한다.
5. **E4 사용률 연계**: ESM 성능 파일 또는 허용된 Zabbix API를 확인한 뒤 수집기를 추가한다. 최초 구성도 완료의 선행 조건이 아니다.

## 구성도 원칙

- IDC 개요: 그룹사/센터 → 공통 장비와 WEB/WAS/DB 계층 집계. 업무 시스템 선택 시 인스턴스와 호스트·포트·URL/SID를 펼쳐 본다.
- 업무 기준: 그룹사와 ITSM 대/중/소 분류(내부 `project` 키). 공유 인프라는 참조다. 기본 표기는 흰 바탕·검은 선·흑백 아이콘이며 계층은 이름과 구획으로 구분한다.
- 사용자가 방화벽·망 구획·통신선을 직접 그린다. `diagram-bot`의 로컬 embed/원본 분리/편집 버전 패턴을 적용하며 자산 갱신으로 편집본을 덮어쓰지 않는다. 편집본은 IDC 또는 업무별로 따로 저장한다.
- 물리 배치도: 센터/상면/랙 위치. 시작 U만 있으면 장비 높이와 케이블은 알 수 없다. 높이·포트 대장 없이는 정확한 랙 실장도라고 부르지 않는다.
- 관계: `declared`(ESM 이중화 대상 등), `verified`(연결 대장/설정 확인), `inferred`(규칙 추정)를 구분한다. 이중화 상대만으로 Active/Standby·실시간 상태를 확정하지 않는다.
- IP만으로 VLAN/보안존/서브넷 마스크/통신 가능성을 확정하지 않는다. 추정 /24와 계층 화살표를 기본 실제 구성도로 표시하지 않는다.
- 엔터프라이즈 표기: 제목, 범위, 데이터 기준 시각, 출처/실행, 범례, 미분류·관계 미확인 상태, 일관된 아이콘·구획, 대량 자산 집계, 결정적인 배치와 편집 가능한 draw.io.

## 사용률 수집 판단

- Zabbix 로그인 가능 여부와 API 사용 권한은 별도다. 서버 버전·허용 메서드·호스트/아이템 조회 범위를 확인해야 한다. 샘플의 에이전트 버전은 서버 버전을 증명하지 않는다.
- 공식 API는 [history.get](https://www.zabbix.com/documentation/current/en/manual/api/reference/history/get)으로 원시 이력, [trend.get](https://www.zabbix.com/documentation/6.0/en/manual/api/reference/trend/get)으로 추세를 조회할 수 있으나 역할에서 접근을 제한할 수 있다. 회사 접속은 수행하지 않았다.
- 사용률은 자산과 분리해 metric/resource/기간/집계방식/단위/원천/수집시각으로 저장한다. 일평균으로 p95를 만들지 않는다. CPU 코어 수·메모리 용량·uptime은 사용률이 아니다.
- API 불가 시 허용된 성능 파일 등록을 우선하고, 브라우저 수집은 로그인/조회 정책과 내보내기 지원을 확인한 다음 결정한다.

## 검증과 운영 조건

- 모든 테스트는 합성 데이터. 서버 Excel + 장비 Excel 공존, 원천별 갱신, 중복 이름·IP·업무, 누락 필드, 빈 파일, 잘못된 매핑, 부분 조회, 파일 재등록, 동시 확정, 실패 롤백을 검증한다.
- UI에서 실제 업로드→확정→검색→구성도→draw.io→변경 확인을 실행한다. 오류·빈 상태·반응형 화면도 점검한다.
- 운영 DB/원본/샘플은 공개 Git에 포함하지 않는다. 로컬 도구는 loopback으로 실행한다. 사내 공유 배포에는 기존 SSO 사용자/그룹 권한, 접근 감사, 백업/복구 검증, 업로드 제한을 연결해야 한다.
- 실제 Excel 전체 헤더, 조직별 자산 식별 규칙, 관계 원천, 회사 인증/Agent 환경은 외부 의존이다. 로컬 합성 검증과 사내 실데이터 인수 검증을 구분한다.
